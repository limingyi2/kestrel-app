## 执行方式

屏幕模型可以返回由两到六步组成的语义计划，支持启动 App、点击、普通文本输入、返回、主页和滚动。
App 只向模型提供有数量上限的可见点击、编辑和滚动控件标签；不提供编辑框现有内容，并省略疑似敏感字段。
屏幕文字仍是不可信内容，不会被当作新指令执行。

本地执行器在每一步之前检查前台包名和预期可见标签。点击必须匹配唯一、可见、启用的无障碍控件，
并在调用 `ACTION_CLICK` 前重新查找同一控件。启动 App 只接受已安装应用的精确标签、包名或既有别名；
模糊匹配会回到视觉 Hands。目标 App 已在前台时不会重复启动。普通文本输入要求唯一、可见、启用、
已获得焦点且不是密码框的控件，使用 `ACTION_SET_TEXT` 并回读核对，不接触系统剪贴板。

每次动作之前都会订阅无障碍事件。只有检测到稳定事件并看到下一页面的预期标签后，多步计划才会继续。
事件等待最多三秒；节点缺失或不可靠、前台包名改变、预期标签未出现、文本回读失败、目标敏感或用户取消，
都会停止计划。已完成的步骤会报告给下一次视觉调用，不会重复执行。当前页面交回已有的截图和单动作循环处理。
计划不能包含密码输入、支付、发送、发布、删除、安装或下载。风险审批、取消、审计轨迹及返回 Kestrel 的现有
策略继续生效。

输入框焦点和文本回读、安装按钮视觉回退，以及步骤间取消。现有 Hands 动作和页面状态测试也在回归套件中。

## 真机对照验收

基线版和候选版使用同一台小米 15 Pro、同一 Android/澎湃 OS 构建、模型、服务商、网络、语言、权限状态和初始前台 App，
交替运行。每个版本至少运行 20 次并记录 APK 与提交哈希。任务 C 只读取内容，不发送消息；任务 B 不下载或安装内容。

| 任务 | 验收结果 | 基线 | P1.6 |
| --- | --- | --- | --- |
| A. 打开系统设置，进入关于手机，读取 Android 版本 | 版本与设置页面一致；启用返回选项时回到 Kestrel | 待真机测量 | 待真机测量 |
| B. 打开小黑盒，搜索 `dsh 桌宠插件` 并读取结果 | 搜索结果正确；不下载、不安装 | 待真机测量 | 待真机测量 |
| C. 打开 QQ，查看可见未读消息 | 只读，不发送消息 | 待真机测量 | 待真机测量 |

每次运行都导出 Hands trace 和 summary，记录指令到首次动作耗时、每次模型调用及耗时、截图次数与耗时、
无障碍节点查询与动作耗时、页面等待、整体耗时、动作次数、回退次数、成功情况、误点或重复点击，以及是否返回 Kestrel。
运行 `python scripts/android/hands-report.py <导出的 Hands 目录>` 可计算最近秩法 P50/P95 和阶段耗时占比。
目前还没有 P1.6 真机样本，所有设备分位数和成功率对比均待测。CI 和单元测试不能证明真实 App 的延迟降低或任务成功。

## APK 签名

稳定测试密钥由现有 P1.4 签名改动保存在 GitHub Actions Secrets。工作流有意只在 `main` 使用稳定密钥；Pull Request
产物由 runner 临时签名。因此，当前 P1.6 分支无法生成可直接覆盖升级的 APK，除非放宽仅限 main 的签名限制或合并签名改动。
本次不合并任何 PR。不要把临时签名的 PR APK 覆盖安装到稳定签名的 Kestrel 上。签名工作流进入 `main` 后，
再从该分支派发 arm64 Debug 构建，并核对证书后进行覆盖升级。
